# Secure Boot Claim Boundary

## What this track is

Architecture, development signing tooling, and checklists for a future GunnchOS secure boot chain. **Not production secure boot.**

## Allowed claims

| Claim | Allowed? |
|-------|----------|
| Secure boot architecture documented | Yes |
| Development signing keys generated locally | Yes |
| Release manifest signed with dev keys | Yes (dev only) |
| Secure boot checklist exists | Yes |

## Not allowed claims

| Claim | Required evidence (not present) |
|-------|----------------------------------|
| Production secure boot enabled | Signed bootloader, kernel, initrd, verified boot chain on hardware |
| TPM / measured boot active | PCR quotes, attestation logs on reference hardware |
| Rollback protection enforced | Anti-rollback fuses or verified monotonic counters tested |
| Recovery key process validated | Hardware recovery drill with signed report |

## Development vs production keys

- **Development keys** live in `security/secure_boot/dev_keys/` (gitignored). Generated by `scripts/generate_dev_signing_keys.sh`.
- **Production keys** are not in this repository. Production signing requires HSM-backed key ceremony and separate audit trail.

## Beta gate

`secure_boot` status must remain **prototype** until boot-chain verification evidence exists on reference hardware.
