# Accessibility Checklist (Gate 6 harness)

**Claim boundary:** `OS_PHYSICAL_BOOT_PENDING` for device-boot claims; accessibility dry-run may still document UI intent.

- [ ] Text scaling supported (or gap documented)
- [ ] High-contrast / reduced-motion options documented
- [ ] Keyboard / D-pad / alternative input path considered
- [ ] Screen-reader / TalkBack path documented where applicable
- [ ] Low-cost device constraints acknowledged
- [ ] Results labeled synthetic when run on emulated profiles

Accessibility review of mocks is not physical boot evidence.
